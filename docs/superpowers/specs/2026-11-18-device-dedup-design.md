# กรองจอซ้ำตอนสแกนให้แข็งแรงขึ้น

## ปัญหา

เพื่อนเปิด MuMu 6 จอ แต่สแกนแล้วได้ 10 จอ:

```
127.0.0.1:16416 … 127.0.0.1:16576   (6 จอจริง)
127.0.0.1:5561
emulator-5556, emulator-5558, emulator-5560
```

MuMu บางเวอร์ชันเปิดพอร์ตชุด 555x คู่กับ 16xxx ให้แต่ละจอ ADB จึงเห็นจอเดียวกันหลายที่อยู่
(`emulator-N` คือพอร์ต N+1 → `emulator-5560` กับ `127.0.0.1:5561` คือการเชื่อมต่อเดียวกัน)

`MuMuController.get_unique_devices()` ควรตัดตัวซ้ำด้วย `ro.serialno` แต่หลุด เพราะ
- timeout 2 วินาที — เปิดหลายจอพร้อมกันแล้วตอบไม่ทัน
- ถ้า `ro.serialno` ว่างและไม่มี `wlan0` จะ fallback เป็นชื่อที่อยู่เอง → ทุกที่อยู่ "ไม่ซ้ำ" เสมอ
- ตัวที่เก็บไว้คือตัวที่เจอก่อน บางทีเหลือ `emulator-xxxx` แทน `127.0.0.1:16xxx`

ผลเสียจริง: จอเดียวถูกแจกบัญชี 2 บัญชีพร้อมกัน บอทกดชนกันเอง

## ขอบเขต

แก้ที่ `get_unique_devices()` ใน `mumu_controller.py` ที่เดียว — ทั้ง `scan_and_connect_all()`
และ `Api.connect_manual()` เรียกผ่านตัวนี้ และ Tkinter (`gui.py`) ได้ผลด้วยโดยไม่ต้องแก้

## ดีไซน์

### 1. รวมชื่อเล่นของการเชื่อมต่อเดียวกันก่อน (ไม่ต้องถามเครื่อง)

`emulator-N` ≡ `127.0.0.1:{N+1}` ≡ `localhost:{N+1}` — จับกลุ่มเป็นตัวเดียวทันที

### 2. ระบุตัวตนด้วยหลายค่า

ยิง ADB ครั้งเดียวต่อกลุ่ม:
`getprop ro.serialno; getprop ro.boot.serialno; settings get secure android_id`

- timeout 5 วินาที ลองซ้ำ 1 ครั้งถ้าพลาด
- กุญแจ = ค่าที่ไม่ว่างทั้งหมดต่อกัน (ตัดค่าไร้ความหมาย `""`, `unknown`, `null`)
  ใช้ทุกค่ารวมกันเพื่อให้ "ซ้ำ" ได้เฉพาะเมื่อทุกค่าตรงกัน → จอโคลนที่บังเอิญ serial เดียวกัน
  แต่ android_id ต่างกันจะไม่ถูกรวมผิด
- **ไม่ fallback เป็น MAC หรือชื่อที่อยู่อีกต่อไป**

### 3. เลือกตัวที่จะเก็บแบบแน่นอน

ในกลุ่มที่ซ้ำ เก็บตามลำดับ: `127.0.0.1:` พอร์ต ≥ 16384 → `127.0.0.1:` พอร์ตอื่น → `emulator-*` → อื่น ๆ
ตัวที่ตัดทิ้ง: สั่ง `adb disconnect` เฉพาะที่อยู่แบบ `ip:port` (เหมือนเดิม) ส่วน `emulator-*` ข้ามไป

ลำดับผลลัพธ์คงตามลำดับเดิมของ `adb devices` (เอาตัวที่ถูกเก็บไว้ตำแหน่งของกลุ่ม)

### 4. ระบุตัวตนไม่ได้ → เก็บไว้ แต่บอก

ถ้าถามไม่ได้ทุกค่า ยังเก็บไว้ (ไม่ซ่อนจอจริง) แต่ใส่หมายเหตุ
`"⚠️ ระบุตัวตน <addr> ไม่ได้ — อาจเป็นจอซ้ำ"` และหมายเหตุ `"ตัดจอซ้ำ <addr> (= <kept>)"` ทุกครั้งที่ตัด
เก็บไว้ที่ `controller.last_dedup_notes` (list[str]) — `Api.scan()` และ `Api.connect_manual()`
ดันเข้า log ของหน้าเว็บ (ตัด = info, ระบุไม่ได้ = warn)

## เทส — `tests/test_device_dedup.py`

ใช้ controller ปลอม (override `run_adb_cmd` / `disconnect_device`) ไม่ยิง ADB จริง:

1. เคสเพื่อน: 6 จอ 16xxx + `5561` + `emulator-5556/5558/5560` (ตัวซ้ำมี id ตรงกับจอ 16xxx) → เหลือ 6 จอ 16xxx
2. `emulator-5560` + `127.0.0.1:5561` โดยถามตัวตนไม่ได้เลย → รวมเป็น 1 จากกฎชื่อเล่น เก็บ `127.0.0.1:5561`
3. ตัวซ้ำมาก่อนใน `adb devices` → ยังเก็บ `127.0.0.1:16xxx`
4. serial ตรงกันแต่ android_id ต่าง → นับเป็น 2 จอ
5. ถามตัวตนไม่ได้ (ไม่มี alias) → ยังอยู่ในลิสต์ และมีหมายเหตุ ⚠️
6. ครั้งแรก timeout ครั้งที่สองได้ → ใช้ค่าครั้งที่สอง
7. เครื่องปกติ (ทุกจอ id ไม่ซ้ำ) → ผลเหมือนเดิมทุกตัว ลำดับเดิม
8. ไม่สั่ง disconnect กับ `emulator-*`
