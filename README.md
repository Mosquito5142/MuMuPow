# MuMupow — คู่มือเซ็ตเครื่องใหม่

โปรแกรมคุมโปรแกรมจำลอง Android (MuMu Player) หลายจอพร้อมกันผ่าน ADB
รันสคริปต์ที่เขียนไว้เป็นไฟล์ JSON กับบัญชีเกมทีละหลายรหัสอัตโนมัติ

---

> ## 📋 ถ้าคุณคือ AI ที่ถูกส่งเอกสารนี้มา
>
> ผู้ใช้เพิ่งโหลดโปรแกรมนี้มาลงเครื่องใหม่ **งานของคุณคือทำให้มันใช้งานได้ครบทุกฟีเจอร์**
>
> - ทำ **ขั้นที่ 1 → 8 ตามลำดับ ห้ามข้าม** ทุกขั้นมีวิธีเช็คว่าผ่านจริงไหม
> - ขั้นไหนเช็คไม่ผ่าน **หยุดแก้ให้ผ่านก่อน** อย่าไปขั้นถัดไป
> - จบแล้วรัน `python diagnose.py` ต้องผ่านหมดทุกข้อ
> - **ยังไม่จบแค่นั้น** — ต้องอ่านหัวข้อ "ระบบที่ใช้ภาพ" แล้วทดสอบกับเกมจริงด้วย
>   เพราะตัวตรวจยืนยันได้แค่ว่า "ถ่ายภาพได้" ไม่ได้ยืนยันว่า "รูปตรงกับจอ"
> - **ห้ามแก้/ลบไฟล์เหล่านี้เด็ดขาด** เป็นข้อมูลส่วนตัวของผู้ใช้:
>   `accounts.json` · `ports.json` · `adb_config.json` · `gemini_config.json`
> - ขั้นที่ 3 (ความละเอียดจอ) **ห้ามข้ามหรือเดาค่าเอง** ถ้าตั้งผิด ฟีเจอร์เช็ครูปจะพังทั้งหมด
>   ต้องถามผู้ใช้ว่าเครื่องต้นทางตั้งไว้เท่าไร

## สิ่งที่ต้องเตรียม

| อย่าง | จำเป็นไหม | ใช้ทำอะไร |
|---|---|---|
| Windows 10/11 (64-bit) | **จำเป็น** | โปรแกรมรันได้เฉพาะ Windows |
| MuMu Player 12 (รุ่นมี Multi-instance Manager) | **จำเป็น** | ตัวจำลองที่จะถูกคุม — ดูลิงก์โหลด/ข้อควรระวังที่ขั้นที่ 3 |

| `ADBKeyboard.apk` | ถ้าจะพิมพ์ไทย | พิมพ์ภาษาไทย/ยูนิโค้ดเข้าเกม |

## ขั้นที่ 1 — เปิด Virtualization (VT) ใน BIOS

ถ้าไม่เปิด MuMu จะรันโหมดซอฟต์แวร์ซึ่งช้ามาก จนโปรแกรมถ่ายภาพหน้าจอไม่ทัน
(โปรแกรมรอภาพสูงสุด **15 วินาที** เกินกว่านั้นถือว่าล้มเหลว)

**เช็ค:** Task Manager → Performance → CPU → ดูบรรทัด **Virtualization**

- `Enabled` = ผ่าน ไปขั้นต่อไป
- `Disabled` = รีสตาร์ทเข้า BIOS เปิด **Intel VT-x** หรือ **AMD-V** (แล้วแต่ซีพียู)

## ขั้นที่ 2 — ลงไดรเวอร์การ์ดจอตัวจริง

เครื่องที่เพิ่งลง Windows ใหม่มักใช้ไดรเวอร์พื้นฐานของ Microsoft ซึ่งทำให้ MuMu
เรนเดอร์ภาพในแบบที่ ADB **ถ่ายภาพออกมาได้เป็นจอดำ** → ฟีเจอร์เช็ครูปพังทั้งหมด

ลงไดรเวอร์จากเว็บผู้ผลิตให้ตรงรุ่น: NVIDIA / AMD / Intel

**เช็ค:** Device Manager → Display adapters → ต้องขึ้นชื่อรุ่นการ์ดจอจริง
ไม่ใช่ `Microsoft Basic Display Adapter`

## ขั้นที่ 3 — ลง MuMu แล้วตั้งความละเอียดให้ตรงเครื่องต้นทาง ⚠️

**นี่คือขั้นที่พลาดกันบ่อยที่สุด และเป็นสาเหตุอันดับ 1 ที่ "กดจอได้ แต่เช็ครูปไม่ได้เลย"**

สคริปต์เก็บ "ภาพตัวอย่าง" ไว้ในตัวเอง แล้วเทียบกับหน้าจอตอนรัน
การเทียบภาพนี้ **ไม่มีการย่อ/ขยายอัตโนมัติ** — ขนาดพิกเซลต้องเท่าเดิมเป๊ะ ๆ
ถ้าความละเอียดต่างจากเครื่องที่ทำสคริปต์แม้แต่นิดเดียว **จะหาไม่เจอทั้งหมด**

### โหลด MuMu Player 12 จากไหน — ต้องรุ่นที่รองรับหลายจอเท่านั้น

โปรแกรมนี้อาศัยพอร์ตแบบ `16384, 16416, 16448, …` (เพิ่มทีละ 32 ต่อหนึ่งจอ) ซึ่งมีเฉพาะใน
**MuMu รุ่นที่มี "ตัวจัดการหลายจอ" (Multi-instance Manager)** เท่านั้น — คือรุ่น 12 เป็นต้นไป

**MuMu รุ่นเก่า (6/7) ใช้ไม่ได้** เพราะเปิดได้จอเดียว พอร์ตคงที่ที่ `127.0.0.1:7555`
เสมอ ไม่มีระบบ 16384+ ให้ต่อหลายจอ — สแกนพอร์ตในโปรแกรมนี้จะไม่เจอ หรือเจอแค่จอเดียว

ลงจากเว็บทางการเท่านั้น (หลีกเลี่ยงเว็บโหลดเถื่อน/ตัวติดตั้งจากที่อื่น — เสี่ยงมัลแวร์):

| เว็บทางการ | ใช้ได้ไหม |
|---|---|
| <https://mumu.163.com/> (เวอร์ชันจีน) | ✅ ใช้ได้ — พอร์ตสกีมเดียวกัน |
| <https://www.mumuplayer.com/> (เวอร์ชันสากล/อังกฤษ) | ✅ ใช้ได้ — บริษัทเดียวกัน (NetEase) พอร์ตสกีมเดียวกัน |

ทั้งสองเว็บเป็นของ NetEase เหมือนกัน ต่างกันแค่ภาษาอินเทอร์เฟซกับเซิร์ฟเวอร์ดาวน์โหลด
**เลือกอันไหนก็ได้** ใช้กับโปรแกรมนี้เหมือนกัน — เว็บสากลสะดวกกว่าถ้าไม่ถนัดภาษาจีน

ระหว่างติดตั้ง ถ้าเจอตัวเลือก **Android 12 กับ Android 15** ให้เลือกให้ตรงกับที่เครื่อง
ต้นทางใช้ (ถามเจ้าของสคริปต์) เพราะเป็นคนละเอนจิ้นย่อย หน้าตา/ตำแหน่งเมนูอาจต่างกันเล็กน้อย

**เช็คว่าได้รุ่นที่ถูก:** เปิด MuMu แล้วต้องเห็นไอคอน **"ตัวจัดการหลายจอ" (Multi-instance
Manager)** หรือปุ่ม "เปิดจอใหม่/新建" — ถ้าไม่มีปุ่มนี้เลย แปลว่าได้รุ่นเก่าผิดเวอร์ชัน

1. ลง MuMu Player 12 (จากเว็บทางการด้านบน) แล้วเปิดจอให้เข้าหน้าโฮม
2. **ถามผู้ใช้ว่าเครื่องต้นทางตั้งความละเอียดกับ DPI ไว้เท่าไร**
   (สั่งบนเครื่องต้นทางได้ด้วย `adb -s 127.0.0.1:16384 shell wm size` และ `wm density`)
3. MuMu → ตั้งค่า → **จอภาพ** → ความละเอียด → **กำหนดเอง** → ใส่ให้ตรง
4. ใส่ **DPI** ให้ตรงด้วย
5. รีสตาร์ทจอ

> **ค่าของชุดสคริปต์นี้:** ความละเอียด `__________` DPI `__________`
> *(เจ้าของสคริปต์กรอกช่องนี้ก่อนส่งต่อ จะช่วยคนรับได้มาก)*

**เช็ค:**

```bash
adb -s 127.0.0.1:16384 shell wm size
```

ต้องได้ค่าตรงกับที่ผู้ใช้บอก

## ขั้นที่ 4 — วางไฟล์โปรแกรม

ตัว `.exe` **ฝังมาแค่หน้าตาโปรแกรมเท่านั้น** ที่เหลืออ่านจากโฟลเดอร์ข้าง ๆ ตัวมันทั้งหมด
ก็อปมาไม่ครบ = ฟีเจอร์นั้นหายไปเลย

```
MuMuPow/
├── MuMupow_new.exe     โปรแกรมหลัก
├── MuMupow.exe         ตัวสำรอง (กิน RAM น้อยกว่า ใช้ตอนเปิดหลายจอมาก)
│
├── macros/             *** สคริปต์หลัก — ขาดไม่ได้
├── script_sets/        *** ชุดคำสั่งย่อยที่สคริปต์เรียกใช้ — ขาดไม่ได้
├── templates/          รูปเทียบแบบไฟล์ (สคริปต์รุ่นเก่าใช้)
├── tessdata/           ข้อมูลภาษา Tesseract (ใช้ตอนอ่านเพชร)
│
├── game_reset.json     ตั้งค่ารีเซ็ตเกมเวลาบัญชีติดปัญหา
├── presets.json        พิกัดที่ตั้งชื่อไว้
├── diamond_ocr.json    พื้นที่อ่านเพชร
├── diagnose.py         ตัวตรวจว่าเซ็ตครบหรือยัง
└── ADBKeyboard.apk     คีย์บอร์ดไทย (ถ้าต้องพิมพ์ไทย)
```

ไฟล์ที่ **สร้างเองตอนใช้งาน** ไม่ต้องก็อปมา และห้ามเอาของเครื่องอื่นมาทับ:
`accounts.json` (รหัสทั้งหมด) · `ports.json` (พอร์ตจอของเครื่องนี้) · `adb_config.json`

**เช็ค:** โฟลเดอร์ `macros/` และ `script_sets/` ต้องมีไฟล์ `.json` อยู่จริง

## ขั้นที่ 5 — ตั้งพาธ ADB

โปรแกรมจะไล่หา `adb.exe` เองตามลำดับ: PATH → Android SDK → LDPlayer
แต่ **ควรตั้งให้ชี้ adb ของ MuMu โดยตรง** จะเสถียรที่สุด (เวอร์ชันตรงกับตัวจำลอง)

ปกติอยู่ที่ (ชื่อโฟลเดอร์ต่างกันเล็กน้อยตามรุ่น CN/สากลที่ลง — ถ้าไม่เจอตามนี้
เปิด Explorer ไปที่ `C:\Program Files\Netease\` แล้วดูว่าโฟลเดอร์ MuMu ชื่ออะไร):

```
C:\Program Files\Netease\MuMuPlayer-12.0\shell\adb.exe
```

เปิด `MuMupow_new.exe` → **ตั้งค่า** → **ที่อยู่ไฟล์ ADB.exe** → วางพาธ → **บันทึกและโหลดใหม่**
(ค่าจะถูกจำไว้ใน `adb_config.json`)

**เช็ค:**

```bash
"C:\Program Files\Netease\MuMuPlayer-12.0\shell\adb.exe" version
```

ต้องได้เวอร์ชัน **1.0.32 ขึ้นไป** (คำสั่งถ่ายภาพ `exec-out` เพิ่งมีในเวอร์ชันนี้)

## ขั้นที่ 6 — หาจอให้เจอ

เปิดจอ MuMu ให้เข้าหน้าโฮมก่อน แล้วในโปรแกรมกด **หน้าแรก → สแกนพอร์ต**

MuMu 12 ใช้พอร์ตแบบ `16384`, `16416`, `16448` … (เพิ่มทีละ 32 ต่อหนึ่งจอ)
ถ้าสแกนไม่เจอ ใส่เองได้ในช่อง `127.0.0.1:16384` แล้วกด **เชื่อม**

**เช็ค:** แถบซ้ายต้องขึ้นรายการจอ และ

```bash
adb devices
```

ต้องเห็นจอขึ้นสถานะ `device`

## ขั้นที่ 7 — ตรวจว่าระบบภาพใช้ได้จริง ⭐

ขั้นนี้สำคัญ เพราะ **"กดจอได้" ไม่ได้แปลว่า "เช็ครูปได้"**

- ขั้นแตะ ใช้แค่ `adb shell input tap x y`
- ขั้นเช็ครูป ต้องผ่าน 3 ชั้น: ถ่ายภาพ (`exec-out screencap`) → แปลงรูป (OpenCV) → เทียบรูป

ชั้นหลังพังได้โดยที่ขั้นแตะยังทำงานปกติ ต้องตรวจแยก

```bash
python diagnose.py
```

ยังไม่มี Python:

```bash
winget install -e --id Python.Python.3.12
pip install opencv-python numpy
```

ตัวตรวจจะไล่เช็คทีละชั้นแล้วบอกว่าพังตรงไหนพร้อมวิธีแก้ **ไม่แก้ไฟล์อะไรทั้งนั้น** รันซ้ำได้

**ผ่าน = ท้ายผลลัพธ์ต้องขึ้น "ทุกอย่างผ่านหมด"**

> ตัวตรวจยืนยันได้แค่ **ชั้นที่ 1 กับ 2** (ถ่ายภาพได้ + OpenCV ทำงาน)
> ส่วน **ชั้นที่ 3 (รูปตรงกับหน้าจอเกมจริงไหม)** ต้องทดสอบกับเกมจริง
> อ่านหัวข้อ **"ระบบที่ใช้ภาพ — ต้องทำอะไรบ้าง"** ด้านล่าง ทำให้ครบก่อนถือว่าจบงาน

### ตรวจด้วยมือ (ถ้าไม่อยากลง Python)

```bash
adb -s 127.0.0.1:16384 exec-out screencap -p > test.png
```

เปิด `test.png` ดู:

| เห็นอะไร | แปลว่า |
|---|---|
| หน้าจอเกมชัดเจน | ผ่าน |
| **ภาพดำล้วน** | ไปอ่าน "อาการ A" ด้านล่าง |
| ไฟล์ 0 KB / เปิดไม่ขึ้น | ไปอ่าน "อาการ A" |
| `unknown command exec-out` | adb เก่า กลับไปขั้นที่ 5 |

## ขั้นที่ 8 — ของเสริม (ทำเฉพาะที่ต้องใช้)

**พิมพ์ภาษาไทยเข้าเกม** — วาง `ADBKeyboard.apk` ไว้ข้างโปรแกรม
แล้วกด **ตั้งค่า → เปิดคีย์บอร์ดไทย** (ต้องทำทีละจอ)

**อ่านจำนวนเพชรอัตโนมัติ** — ต้องมี Tesseract OCR (ไม่ได้ฝังมาใน .exe)
ลงเองก็ได้ หรือแถมมากับโปรแกรมแบบพกพาก็ได้ —
ดูวิธีทั้ง 2 แบบที่หัวข้อ **"ต้องลงโปรแกรมอะไรเพิ่มไหม"** ด้านล่าง

**ให้ AI ช่วยเล่นเนื้อเรื่อง (Story Auto)** — ใส่ Gemini API key ที่ **ตั้งค่า → Gemini API Key**

## ตรวจครั้งสุดท้ายก่อนใช้งานจริง

1. `python diagnose.py` → ผ่านหมด
2. หน้าแรก → เห็นจอครบตามจำนวนที่เปิด
3. หน้าบัญชี → เห็นรายชื่อรหัส (ถ้าผู้ใช้ก็อป `accounts.json` มาแล้ว)
4. หน้าสคริปต์ → เลือกสคริปต์ได้ เห็นขั้นตอนครบ
5. **ลองรันจริง 1 รหัส 1 จอ** แล้วดูแถบคอนโซลล่างสุดว่าเดินครบทุกขั้นไหม

## ระบบที่ใช้ภาพ — ต้องทำอะไรบ้าง (อ่านให้ครบ)

ทุกอย่างมักจะใช้ได้ปกติตั้งแต่แรก **ยกเว้นเรื่องนี้เรื่องเดียว** เพราะมันเป็นส่วนเดียวที่
พึ่งพา 3 อย่างที่เปลี่ยนไปตามเครื่อง: การ์ดจอ · ความละเอียดจอ · หน้าตาเกม ณ ตอนนั้น

### ⭐ ต้องลงโปรแกรมอะไรเพิ่มไหม — ตอบให้ชัดตรงนี้เลย

**เรื่อง "เทียบรูป" (เช็ครูป / จับภาพ / anchor) → ไม่ต้องลงอะไรเลย**

ตัวอ่านภาพ (OpenCV) ถูก **ฝังมาในไฟล์ `.exe` เรียบร้อยแล้ว** พร้อมตัวประกอบที่มันต้องใช้
เครื่องปลายทางไม่ต้องลง Python ไม่ต้องลง OpenCV ไม่ต้องลง Visual C++ Redistributable

| สิ่งที่ระบบเทียบรูปต้องใช้ | อยู่ไหน |
|---|---|
| OpenCV (ตัวเทียบรูป) | ✅ ฝังใน `.exe` แล้ว |
| NumPy | ✅ ฝังใน `.exe` แล้ว |
| Microsoft VC++ Runtime | ✅ ฝังใน `.exe` แล้ว |
| Python | ✅ ฝังใน `.exe` แล้ว |

> ถ้า OpenCV โหลดไม่ได้จริง ๆ **โปรแกรมจะเปิดไม่ขึ้นตั้งแต่แรกเลย** (จอขาว/ไม่มีหน้าต่าง)
> เพราะโค้ดโหลด OpenCV ตั้งแต่ตอนเริ่มโปรแกรม ไม่ได้โหลดตอนจะใช้
> **ดังนั้นถ้าโปรแกรมเปิดได้และกดจอได้ = ตัวอ่านภาพไม่ใช่ปัญหาแน่นอน**
> ปัญหาจะอยู่ที่ "ถ่ายภาพจากจอไม่ได้" (จอดำ) หรือ "รูปไม่ตรงกับจอ" แทน

**เรื่อง "อ่านตัวเลข/ตัวหนังสือจากภาพ" (อ่านเพชร, ดึงรายชื่อชมรม) → อันนี้ต้องลงเพิ่ม**

อันนี้ใช้คนละตัวกัน ชื่อ **Tesseract OCR** และ **ไม่ได้ฝังมาในไฟล์ `.exe`**
ถ้าไม่มี ระบบอ่านเพชรจะไม่ทำงาน (แต่การเช็ครูปยังใช้ได้ปกติ ไม่เกี่ยวกัน)

มี 2 ทางเลือก:

**ทาง ก. ลงตามปกติ** (ปลายทางต้องกดติดตั้งเอง)

ลงจาก <https://github.com/UB-Mannheim/tesseract/wiki>
ที่พาธมาตรฐาน `C:\Program Files\Tesseract-OCR\` โปรแกรมจะหาเจอเอง

**ทาง ข. แถมไปกับโปรแกรมเลย — ปลายทางไม่ต้องลงอะไรเลย** ⭐ แนะนำ

โปรแกรมจะมองหา `tesseract.exe` ใน **โฟลเดอร์ `tesseract/` ข้าง ๆ ตัว exe เป็นอันดับแรก**
ก่อนจะไปหาที่ติดตั้งในเครื่อง เลยแถมแบบพกพาไปได้เลย:

```
MuMuPow/
├── MuMupow_new.exe
└── tesseract/
    ├── tesseract.exe        <- ก็อปมาจากเครื่องที่ลงไว้แล้ว
    └── (ไฟล์ .dll ที่มาด้วยกันทั้งหมด)
```

ทำแบบนี้แล้ว **เครื่องปลายทางแกะ ZIP แล้วใช้ได้ทันที ไม่ต้องติดตั้งอะไรสักอย่าง**

> **สำหรับเจ้าของสคริปต์:** ถ้าจะแจกให้คนอื่นใช้ ทำทาง ข. ไว้เลยจะจบปัญหานี้ถาวร
> ก็อปทั้งโฟลเดอร์จาก `C:\Program Files\Tesseract-OCR\` มาใส่ในโฟลเดอร์ชื่อ `tesseract`
> (เอาเฉพาะ `tesseract.exe` อย่างเดียวไม่พอ ต้องเอา `.dll` มาด้วยทั้งหมด)

**หน้าตาโปรแกรม (WebView2)** — Windows 11 และ Windows 10 ที่อัปเดตแล้วมีมาให้ในตัว
ถ้าเปิดโปรแกรมแล้วได้หน้าต่างว่างเปล่า ให้ลง WebView2 Runtime จาก
<https://developer.microsoft.com/microsoft-edge/webview2/>

### ขั้นตอนไหนบ้างที่ต้องใช้ภาพ

| ใช้ภาพ (พังได้) | ไม่ใช้ภาพ (ปกติจะใช้ได้เลย) |
|---|---|
| `เจอรูปกด` / `รอรูป` (detect_image, wait_for_image) | `แตะ` (tap) |
| `ทางเลือก (ถ้าเจอภาพ)` (if_image) | `ปัด` (swipe) |
| `กดรัวจนเจอรูป` (tap_until_image) | `พิมพ์` (text) |
| `กดรอบๆ การ์ดจนเจอรูป` (tap_around_until_image) | `ปุ่มระบบ` (keyevent) |
| `ตอบคำถาม` (answer_quiz) | `รอ` (sleep) |
| `เคลียร์โฆษณา` (clear_ads_loop) | `เปิด/ปิดแอป` |
| `หาด่านสีเหลือง` / `Story Auto` | `แตะข้อความ` (tap_text) |
| `อ่านเพชร` (read_diamond — ใช้ Tesseract ด้วย) | `ดึง OTP` (fetch_otp) |

> ⚠️ **สำคัญ:** ขั้น "แตะ" ธรรมดา **ก็ใช้ภาพได้** ถ้ามันตั้ง **anchor** ไว้
> (รูปเล็ก ๆ ที่ต้อง "เห็นก่อนถึงจะกด" เอาไว้กันกดมั่วตอนจอยังโหลดไม่เสร็จ)
>
> **วิธีดูว่าบล็อกไหนมี anchor:** เปิดผังงาน แล้วดูที่ขวาของบล็อก
> ถ้ามี **รูปย่อขอบสีเหลือง** ติดอยู่ = บล็อกนั้นใช้ภาพ
>
> **นี่คือเหตุผลที่บางสคริปต์ที่ดู "กดเฉย ๆ" ก็ยังพัง** ทั้งที่ไม่มีขั้นเช็ครูปสักขั้น

### ต้องผ่าน 3 ชั้น ชั้นไหนพังก็จบเหมือนกัน

```
[ชั้น 1] ถ่ายภาพจากจอ    adb exec-out screencap -p
             ↓ ได้ PNG กลับมาไหม / ภาพดำหรือเปล่า
[ชั้น 2] แปลงเป็นรูป      OpenCV (cv2.imdecode)
             ↓ ไลบรารีทำงานไหม
[ชั้น 3] เทียบรูป         cv2.matchTemplate -> คะแนน 0.00 - 1.00
             ↓ คะแนนถึงเกณฑ์ 0.80 ไหม
          เจอ / ไม่เจอ
```

ขั้น "แตะ" ใช้แค่ `adb shell input tap x y` ไม่แตะทั้ง 3 ชั้นนี้เลย
มันเลยยังทำงานได้ปกติทั้งที่ระบบภาพพัง — **"กดจอได้" จึงไม่ได้แปลว่า "เช็ครูปได้"**

### เช็คทีละชั้น

**ชั้น 1 และ 2** — รัน `python diagnose.py` มันตรวจให้ครบแล้ว
(ถ่ายได้ไหม · กี่ไบต์ · ใช้เวลากี่วินาที · เป็นจอดำหรือเปล่า · OpenCV เทียบภาพถูกต้องไหม)

**ชั้น 3** — ต้องทดสอบกับหน้าจอเกมจริง ใช้เครื่องมือในโปรแกรม (หัวข้อถัดไป)

### เครื่องมือทดสอบในโปรแกรม ⭐ (ตัวนี้สำคัญที่สุด)

โปรแกรมมีปุ่มยิงทดสอบภาพกับหน้าจอจริง ณ วินาทีนั้นได้เลย ไม่ต้องรันสคริปต์ทั้งชุด

1. เปิดเกมในจอให้อยู่หน้าที่ต้องการทดสอบ (หน้าที่รูปนั้นควรจะโผล่)
2. ในโปรแกรม: **สคริปต์ → เปิดผังงาน** → คลิกบล็อกที่ใช้ภาพ
3. กดปุ่ม **"ทดสอบว่าเจอไหม"** (บล็อกกดรอบๆ จะมี "ทดสอบภาพเป้าหมาย" กับ "ทดสอบภาพการ์ด" แยกกัน)

ผลที่ได้:

| ผล | ความหมาย |
|---|---|
| `✅ เจอบนจอตอนนี้ ที่ (x,y)` | ชั้น 3 ผ่าน ภาพนี้ใช้ได้ |
| `❌ ไม่เจอ — No match found (best confidence: 0.62)` | เจอแต่ไม่เหมือนพอ ดูตารางล่าง |
| `❌ ไม่เจอ — แคปจอไม่ได้` | ชั้น 1 พัง ไม่ใช่เรื่องภาพ → อาการ A |

**ตัวเลข `best confidence` คือกุญแจ** มันบอกว่าเหมือนแค่ไหน (เกณฑ์ผ่านปกติคือ 0.80):

| คะแนน | แปลว่า | ทำยังไง |
|---|---|---|
| 0.95 – 1.00 | ตรงเป๊ะ | ไม่ต้องทำอะไร |
| 0.80 – 0.94 | ผ่านแต่ไม่เยอะ | ใช้ได้ แต่ถ้าพลาดบ่อยให้จับภาพใหม่ |
| 0.60 – 0.79 | ใกล้เคียง แต่ไม่ผ่านเกณฑ์ | ลดเกณฑ์เป็น 0.7 **หรือ** จับภาพใหม่ (แนะนำ) |
| ต่ำกว่า 0.60 | คนละภาพกันเลย | **ต้องจับภาพใหม่** ลดเกณฑ์ไม่ช่วย มีแต่จะกดมั่ว |

ช่องแก้เกณฑ์: เลือกบล็อกนั้น → **"ความเหมือนขั้นต่ำ (0–1, ปกติ 0.8)"**

> อย่าลดเกณฑ์ต่ำกว่า 0.6 เด็ดขาด มันจะเริ่ม "เจอ" ในที่ที่ไม่มีจริง แล้วบอทจะกดมั่วทั้งรอบ

### จับภาพใหม่เอง — ทางออกที่ชัวร์ที่สุด

ถ้าคะแนนต่ำ **ไม่ต้องไปไล่ปรับความละเอียดให้ตรงเป๊ะก็ได้** จับภาพใหม่จากจอตัวเองเร็วกว่าและชัวร์กว่า

1. เปิดเกมให้อยู่หน้าที่ต้องการ
2. **สคริปต์ → เปิดผังงาน** → คลิกบล็อกที่ใช้ภาพ
3. กดปุ่มตั้งภาพ (ชื่อจะต่างกันตามชนิดบล็อก):
   - `ตั้งภาพเงื่อนไขจากจอ` — บล็อกทางเลือก (if_image)
   - `ตั้งภาพจากจอ (ลากกรอบ)` — บล็อกรอรูป / เจอรูปกด
   - `ตั้งภาพเป้าหมาย (modal)` — บล็อกกดรอบๆ
   - `ตั้งภาพการ์ด (ที่จะกดรอบๆ)` — รูปการ์ดที่จะเล็งกด
   - `อัดภาพรอก่อนกด` — anchor ของบล็อกแตะ/ปัด
4. ลากกรอบครอบเฉพาะส่วนที่ **ไม่เปลี่ยนแปลง** (ดูข้อควรระวังล่าง)
5. กด **ทดสอบว่าเจอไหม** ให้ขึ้น ✅ ก่อน
6. **บันทึก** สคริปต์

**ลากกรอบยังไงให้ทน:**

| ควรครอบ | ไม่ควรครอบ |
|---|---|
| ไอคอน/สัญลักษณ์ที่คงที่ | ตัวเลข (เพชร เงิน เวลา ที่เปลี่ยนตลอด) |
| หัวข้อ modal | ชื่อผู้เล่น / เลเวล |
| กรอบปุ่มที่รูปทรงชัดเจน | พื้นหลังที่มีอนิเมชัน |
| ขนาดพอประมาณ ~50–200px | ทั้งหน้าจอ (ช้าและเปราะ) หรือเล็กกว่า 20px (เจอมั่ว) |

### ทำไมภาพถึงไม่ตรง ทั้งที่เป็นเกมเดียวกัน

การเทียบภาพในโปรแกรมนี้ **ไม่มีการย่อ/ขยายอัตโนมัติ** ต้องเหมือนกันระดับพิกเซล
สิ่งพวกนี้ทำให้พิกเซลเปลี่ยนได้ทั้งหมด:

1. **ความละเอียด / DPI ของ MuMu ไม่ตรง** ← สาเหตุอันดับ 1 (ขั้นที่ 3)
2. **ระดับกราฟิกในเกมไม่ตรง** — เกมส่วนใหญ่มี ต่ำ/กลาง/สูง ซึ่งเปลี่ยนความคมและเงา
   → ตั้งให้ตรงกับเครื่องที่ทำสคริปต์
3. **ภาษาในเกมไม่ตรง** — ถ้ารูปที่จับมามีตัวหนังสือ เปลี่ยนภาษาแล้วจบเลย
4. **ธีม/สกินตามอีเวนต์** — บางเกมเปลี่ยนพื้นหลังปุ่มตามเทศกาล รูปเก่าจะไม่ตรงชั่วคราว
5. **มีอะไรบังอยู่** — ป๊อปอัพ, แถบแจ้งเตือน, ปุ่มลอยของ MuMu

### ระบบอ่านตัวเลข (อ่านเพชร) — คนละเรื่องกับการเทียบภาพ

ใช้ **Tesseract OCR** ไม่ใช่การเทียบภาพ ต้องทำ 2 อย่าง:

1. **มี Tesseract ในเครื่อง** — ดูหัวข้อ "ต้องลงโปรแกรมอะไรเพิ่มไหม" ด้านบน
   เช็คว่ามีแล้วหรือยัง: `python diagnose.py` จะบอกในข้อ 8
2. **ตั้งพื้นที่ตัวเลขใหม่บนเครื่องนี้** — อื่นๆ → เครื่องมือ → **เปิดตั้งค่าระบบเพชร**
   → แคปจอ → ลากกรอบครอบเฉพาะตัวเลข → ทดสอบอ่าน → บันทึก

พื้นที่นี้เก็บใน `diamond_ocr.json` ซึ่งผูกกับความละเอียดจอ **ถ้าจอไม่ตรงต้องลากใหม่**

> โฟลเดอร์ `tessdata/` ที่มากับโปรแกรมเป็นข้อมูลภาษาเพิ่มเติม (ไทย/ญี่ปุ่น/เกาหลี/จีน)
> ใช้กับฟีเจอร์ "ดึงรายชื่อสมาชิกชมรม" ของแอปตัวเก่า (`MuMupow.exe`) เท่านั้น
> ส่วนการอ่านเพชรใช้ภาษาอังกฤษที่มากับ Tesseract อยู่แล้ว

### เช็คลิสต์สั้น ๆ

```
[ ] เทียบรูป: ไม่ต้องลงอะไร (ฝังใน exe แล้ว)
[ ] จะใช้อ่านเพชร: มี Tesseract หรือมีโฟลเดอร์ tesseract/ ข้าง exe

```

## แก้ปัญหาตามอาการ

### A. ถ่ายภาพได้จอดำ หรือได้ไฟล์ว่าง → เช็ครูปไม่ได้เลย

ADB ถ่ายภาพไม่เห็นสิ่งที่ MuMu วาดผ่าน GPU

1. MuMu → ตั้งค่า → จอภาพ → **โหมดการเรนเดอร์** สลับทีละแบบ: `DirectX` → `OpenGL` → `Vulkan`
2. **รีสตาร์ทจอทุกครั้งที่เปลี่ยน** แล้วทดสอบ `screencap` ใหม่
3. ยังดำทุกแบบ → ปิด "เร่งความเร็วด้วยฮาร์ดแวร์" หรือย้อนไปทำขั้นที่ 2 (ไดรเวอร์จอ)

### B. ถ่ายภาพได้ชัด แต่สคริปต์ยังบอก "ไม่เจอรูป"

ความละเอียดจอไม่ตรงกับเครื่องที่ทำสคริปต์ → **กลับไปทำขั้นที่ 3 ให้ถูกต้อง**

`diagnose.py` ข้อ 6 จะเตือนให้เองถ้าเจอรูปในสคริปต์ที่ใหญ่กว่าจอปัจจุบัน
(กรณีนั้นหาไม่เจอ 100% ไม่ว่าจะลดเกณฑ์ความเหมือนแค่ไหน)

### C. กดจอไม่ตรงตำแหน่ง

ความละเอียด/DPI ไม่ตรงเช่นกัน → ขั้นที่ 3

### D. ถ่ายภาพช้า / ขึ้น `Command timed out`

VT ยังไม่เปิด → ขั้นที่ 1 · และเพิ่ม CPU/RAM ให้ MuMu ในหน้าตั้งค่าของ MuMu

```bash
python web_app.py           # ตัวใหม่ (หน้าตาเว็บ)
python main.py              # ตัวเก่า (Tkinter)
python -m pytest tests/ -q  # ต้องผ่านทั้งหมดก่อนและหลังแก้
```

Build:

```bash
python -m PyInstaller --clean MuMupow_web.spec   # ได้ dist/MuMupow_new.exe
python -m PyInstaller --clean MuMupow.spec       # ได้ dist/MuMupow.exe
```

แก้ไฟล์ใน `webui/*.js` แล้ว **ต้องเพิ่มเลข `?v=` ในแท็ก `<script>` ของ `webui/index.html` ด้วย**
ไม่งั้น WebView2 จะใช้ไฟล์เก่าที่แคชไว้ แล้วดูเหมือนแก้ไม่ติด

รายละเอียดสถาปัตยกรรมภายในอยู่ใน `CLAUDE.md`

## สรุปสั้นสำหรับ AI

```
เป้าหมาย: ทำให้โปรแกรมใช้ได้ครบทุกฟีเจอร์บนเครื่องใหม่

1. VT เปิดใน BIOS หรือยัง          -> Task Manager > CPU > Virtualization
2. ไดรเวอร์การ์ดจอตัวจริงหรือยัง    -> Device Manager > Display adapters
3. ความละเอียด MuMu ตรงต้นทางไหม   -> ถามผู้ใช้ ห้ามเดา  *** สำคัญที่สุด ***
4. ไฟล์ครบไหม                      -> macros/ กับ script_sets/ ต้องมี
5. ตั้งพาธ adb ของ MuMu             -> ตั้งค่า > ที่อยู่ไฟล์ ADB.exe
6. สแกนเจอจอไหม                    -> adb devices ต้องขึ้น device
7. python diagnose.py              -> ต้องผ่านหมด (ยืนยันชั้น 1-2)
8. ของเสริมเท่าที่ผู้ใช้ต้องใช้
9. อ่านหัวข้อ 'ระบบที่ใช้ภาพ' แล้วทำเช็คลิสต์ท้ายหัวข้อให้ครบ (ยืนยันชั้น 3)
   -> เปิดผังงาน กดปุ่ม 'ทดสอบว่าเจอไหม' ต้องขึ้น ✅ กับหน้าจอเกมจริง

ห้ามแก้: accounts.json / ports.json / adb_config.json / gemini_config.json
กดจอได้ ไม่ได้แปลว่าเช็ครูปได้ ต้องผ่านขั้นที่ 7 ถึงจะถือว่าเสร็จ
```
